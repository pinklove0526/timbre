# Milestone 5 - Recording (scope map)

**Done when:** record from the microphone into a new track (from MILESTONE_SCOPE_MAP.md).

Work is split in three phases. **Phase A0** (done, merged) is a capture probe that only measures how `javax.sound.sampled` capture behaves on this machine; it writes no audio. **Phase A** (implemented, awaiting review) is the headless recorder core with a fake capture source; **Phase B** is the UI. Each starts after the user reviews the previous one.

## Settled decisions (user-approved defaults)
1. **Capture:** `javax.sound.sampled` `TargetDataLine` on the system DEFAULT input device, 16-bit signed little-endian PCM, converted to planar float32 (the same scaling as the playback side). The recording rate is the project's sample rate when the project has tracks, 44100 Hz for an empty project (another supported rate only if the probe shows 44100 is unavailable). If the device cannot capture at the project's rate the recording is REFUSED with a message (resampling is deferred).
2. **Channels:** a Mono/Stereo choice, default stereo. No input device picker yet (system default only).
3. **During recording:** a peak level meter, a clipping indicator and the elapsed time. The waveform appears when recording stops; a live-growing waveform is deferred.
4. **Destination:** a NEW track starting at the cursor frame (the selection start). Stopping creates ONE undoable history entry "Record" (an `AddTrackCommand`-style import of the new track).
5. **Locking:** while recording, playback and all edits (including Import, Remove Track, Undo, Redo) are locked; zoom, scroll and track selection stay active. Overdub is deferred (it needs latency compensation).
6. **Keys:** R starts recording; Space or the Stop button stops it. No pause during recording in M5.
7. **Length cap:** auto-stop at 30 minutes with a message (recordings live in memory until file-backed sources exist). The data is kept in chunks (a `ChunkedSampleSource`) so stopping needs no big copy.
8. **This probe phase comes first;** the design below is provisional until its findings are in.
9. **Phases:** A0 probe, A headless recorder core with a fake capture source, B UI.

## Non-goals (M5)
Live waveform while recording, overdub, an input device picker, input gain control, resampling, pause while recording, punch-in, monitoring/playthrough, file-backed recording.

## Design (amended by Phase A0)
Settled by the user for Phase A (prompt `timbre-m5a-implementation.md`); Phase B classes are marked **(B)**.
- **`model.ChunkedSampleSource`** (final, `SampleSource`): equal-size planar float chunks (default 65536 frames). Built through `ChunkedSampleSource.Builder(sampleRate, channelCount, chunkFrames, ChunkFactory)`; `ChunkFactory` is a functional interface `(frames, channels) -> float[][]` (the default allocates; tests inject one that throws `OutOfMemoryError`). `append(float[][] planar, int frames)` (single writer thread; fills the current chunk, starts a new one when full; an `OutOfMemoryError` leaves the stored frames unchanged), `frameCount()`, `build()` (the last chunk may be partial; the Builder is unusable afterwards: `IllegalStateException`). The built source is immutable and thread-safe, `read` follows the `SampleSource` contract, does not allocate and crosses chunk boundaries. A 0-frame source is allowed, but the Recorder never returns one.
- **`audio.CaptureSource`** (interface, styled like `AudioSink`): `open(sampleRate, channels, bufferFrames)` throws `AudioDeviceException`; `start()`; `read(byte[], offset, length)` (blocking, whole frames, 0 after stop or close, never throws because another thread stopped or closed it); `availableBytes()`; `stop()`; `close()`; `bufferFrames()`; `channels()`; `sampleRate()`. Single-use: `start()` after `stop()` or `close()`, or `open`/`start` after `close()`, throws `IllegalStateException`. No position method (A0 finding 7: the device position is unreliable). **`audio.CaptureSourceFactory`**: `create()`.
- **`audio.JavaSoundCaptureSource`** (final): the system DEFAULT input via `AudioSystem.getTargetDataLine(format)` and `line.open(format, bufferFrames * frameBytes)`, 16-bit signed LE; open failures become an `AudioDeviceException` with a user-presentable message; `stop()`/`close()` map to the line and never throw. After `stop()` the bytes reported by `available()` cannot be read (finding 8).
- **PCM16 decoding:** the existing `SampleCodec.decode(..., WavEncoding.PCM_16, ...)` (v / 32768f, de-interleaving into planar float).
- **`audio.ClipWatch`** (pure): `add(frames, fullScaleSamples)` per block; `warning()` when, over the most recent blocks whose frames add up to at least one second, more than 1 % (strictly) of the samples are at full scale (|v| >= 0.999). **`audio.SilenceWatch`** (pure): consecutive frames in blocks whose peak is below -90 dBFS accumulate, a louder block resets; `warning()` from 3 s on.
- **`audio.RecorderState`** (IDLE, RECORDING), **`audio.StopReason`** (USER, LENGTH_LIMIT, OUT_OF_MEMORY, ERROR), **`audio.RecordingResult`** (record: source or null for 0 frames, framesRecorded, reason, suspectedDropouts, estimatedLostFrames, everClipped, silentWarningRaised, errorMessage), **`audio.RecorderListener`** (`stateChanged`, `finished`, both on the capture thread "timbre-capture"; a throwing listener does not kill the thread).
- **`audio.Recorder`** (final, `AutoCloseable`): `Recorder(factory, bufferFrames, maxFrames, nanoClock, chunkFrames, chunkFactory)` plus a convenience constructor (100 ms buffer, 30-minute cap, `System::nanoTime`, 65536-frame chunks). `start(rate, channels)` opens a FRESH source from the factory and starts the daemon thread "timbre-capture"; `stop()` is an asynchronous request; `stopAndWait(timeout)` waits, then escalates once with the source's `stop()`/`close()`; `state()`, `framesRecorded()` (frames read: the elapsed-time source), `pollPeaks(float[])`, `clippingWarning()`, `silentWarning()`, `suspectedDropouts()`, `estimatedLostFrames()`, `close()`.
- **Capture loop** (D1', D2'', 3', 7'): blocks of 1024 frames. Each iteration: end if the cap is reached or a stop was requested; otherwise `availableBytes()` (the D2'' overflow check), then one blocking read; the first data sets tFirstData; decode into reusable buffers; append; update frames read, peaks, ClipWatch and SilenceWatch; a block that passes the cap is trimmed to exactly the cap (LENGTH_LIMIT). END SEQUENCE for USER: read what `availableBytes()` reports (whole frames, never more than available) while the line still runs, then `stop()`, then `close()`. A read error ends with ERROR and keeps the data read so far; an `OutOfMemoryError` from the chunk factory ends with OUT_OF_MEMORY and keeps what was stored. The thread always closes the source, then delivers `stateChanged(IDLE)` and exactly one `finished(result)`.
- **`edit.AddTrackCommand`** gains a constructor with a command name; **`edit.Editor.addRecording(trackName, source, atFrame)`** adds a one-clip track at `atFrame` as the history entry "Record" (refused for 0 frames or a sample rate that differs from the project's).
- **(B) UI:** a Record button and the R key, the level meter and elapsed time, `TransportRules` RECORDING, the messages (refusals, clipping, silence, dropouts, the length cap) and the "Record" wiring.

## Phase A0 findings
Branch `feature/pinklove0526/m5a0-capture-probe`, from develop `de5fa27`. Tool: `CaptureProbe` (test tree, next to `AudioProbe`, same runner); logs in `build-logs/m5a0` (git-ignored), every prediction next to its result in `predictions.txt`. Run on 2026-11-21 with the user's consent (statistics only, no audio stored or printed), in a coffee shop with music, Apple EarPods (3.5 mm, with microphone). Capture ledger: 33.0 s of a 40 s budget (raised from 30 s by the user).

1. **System** (`05-inputs`, `07-inspect`; prediction: plain PulseAudio, contradicted). The sound server is PulseAudio on PipeWire 1.6.5. Default source `alsa_input.pci-0000_00_1f.3.analog-stereo` (built-in analog, ALC256), not a monitor, one port "Microphone" (`analog-input-mic`, no separate headset port), native `s32le` 2 ch 48000 Hz, suspended when idle.
2. **Java mixers and formats** (`05-inputs`; confirmed). Two capture mixers: `alsa_playback.java [default]` (the ALSA default, routed through PipeWire) and `PCH [plughw:0,0]` (direct hardware). Both accept 16- and 24-bit signed LE at 44100 and 48000 Hz, mono and stereo; 32-bit float is not supported. 44100 Hz is available.
3. **Default line** (`06-open`; confirmed). `AudioSystem.getTargetDataLine` returns a `DirectTDL` of `alsa_playback.java [default]`; the actual format always equals the requested one; open takes 21-69 ms; the default buffer is 0.5 s (22050 frames at 44.1 kHz, 24000 at 48 kHz).
4. **Timing with the default buffer** (`06-open`, `17-sustain`; partly contradicted). First data 125 ms after `start()` (predicted 20-250 ms). Every read of 1024 frames returns full, but the data arrives in bursts: 5-6 reads back to back, then about 125 ms of waiting (gap median 0.02-0.31 ms, p95 125.3 ms), not the predicted steady 23.2 ms cadence. `getLongFramePosition` stays about one burst (4600-5600 frames) ahead of the frames read; no overflow in 8 s of continuous reading.
5. **Requested buffer sizes** (`12-buffers`; direction confirmed, smoother than predicted). Requested 40 ms and 100 ms are granted exactly (1764 and 4410 frames). With 100 ms: one read every 25.2 ms (p95 25.4, max 50.6), first data 50.5 ms. With 40 ms: one read every 20.5 ms (p95 30.9, max 41.0), first data 40.8 ms.
6. **Levels: hard clipping at the user's 100 % input level** (`06-open`, `07-inspect`, `11-diag-100pct`, `13-inspect-30pct`, `14-diag-30pct`). The open mode showed peak 0.0 dBFS and RMS -1.4..-0.2 dBFS in all 61 windows. The read-only inspection showed the source volume at 100 % with a base volume of 10 % (-60 dB): about +60 dB of capture gain. `diag` at 100 %: 56 % of the samples at full scale, 72 % of the magnitudes in the top histogram bucket, zero-crossing rate about 1580/s, mean |DC| 0.08: hard clipping of a real signal (hypothesis a), not a stuck line (b: |DC| > 0.5, zero-crossing rate near 0), not a decoding error (c: a byte swap would give a flat histogram and RMS about -4.8 dBFS, offset-binary a DC near -1), not "healthy but loud" (d). After the user lowered the input to 30 % (-31.4 dB, about +28.6 dB over base): no sample at full scale, peaks -19..-13 dBFS, RMS -28..-23 dBFS varying per window, histogram 97.6 % below a quarter of full scale. Quiet gaps could not be observed (continuous music in the room).
7. **Stall and dropouts** (`15-stall`; key point contradicted). During a 1 s pause in reading, `available()` filled to exactly the buffer size and `getLongFramePosition` advanced only by the free buffer space (17244 frames) and then STOPPED; about 0.61 s of audio was lost while the buffer was full, and position-minus-read did not change (4806 before, 4828 after). So the provisional dropout detector (position delta minus frames read) does NOT work on this system. The first reads after the stall returned instantly (buffered old data).
8. **Stop and close** (`16-stop`; partly contradicted). `stop()` from another thread wakes a blocked `read()` within 0.5 ms with a short, frame-aligned count, no exception; `close()` from another thread wakes it within 0.3 ms, no exception, no hang. After `stop()` the bytes still reported by `available()` (7528 and 16600 bytes in two runs) can NOT be read: `read()` returns 0. `start()` again on the same line delivers data after 0.1 ms, which is the stale buffered audio. Close and reopen: first data 125.2 ms. stop + read + close takes 2.4 ms.
9. **Drift** (`17-sustain`; not resolved). Frames read versus wall time gave -2181 ppm over 8 s, but read returns arrive in 125 ms bursts, so the endpoint uncertainty is about +-15600 ppm; the drift is not resolved by this run.
10. **Privacy check:** no `.wav`, `.raw` or `.pcm` file was created (a `find` for audio files newer than the branch start found none); the probe kept only per-window aggregates.

### Amended decisions
Evidence: the findings above. Unchanged: decisions 2, 4, 5, 6, 8 and 9.
- **1'. Capture:** as decision 1 (16-bit signed LE on the default input, 44100 Hz for an empty project, which is available), plus: the line is opened with an explicitly requested buffer of about 100 ms (`open(format, bytes)`), not the 0.5 s default. Reason: the default buffer delivers audio in 125 ms bursts and its first data comes after 125 ms; 100 ms gives one read every ~25 ms and first data after ~50 ms. (40 ms is smoother still, but leaves less headroom against a stalled capture thread.)
- **3'. During recording:** the level meter is refreshed from the reads (about 40 Hz with 1'); the elapsed time and the recorded length are computed from FRAMES READ divided by the rate, not from wall time (the wall-clock drift could not be resolved, and frames read is exactly what the track will contain). New: a sustained-clipping warning. If more than 1 % of the samples in any 1 s span are at full scale (|v| >= 0.999), the UI shows "Input is clipping: lower the input level in the system settings". Timbre never changes the input level itself. Reason: finding 6, a real setup at 100 % clipped 56 % of the samples.
- **7'. Length cap:** counted in frames read (30 minutes x rate), consistent with 3'.
- **Design D1' (stop sequence):** the capture thread ends a recording by reading `available()` rounded down to whole frames while the line is still running (this does not block), then `stop()`, then `close()`. A stopped line is never restarted; every recording opens a fresh line. `stop()` or `close()` from another thread is only a safety net to wake a blocked read, since both return within 1 ms. Reason: finding 8, the data still buffered at `stop()` cannot be read afterwards, and a restart delivers stale audio.
- **Design D2' (dropout detection):** a suspected overflow is detected when `available()` is at least the buffer size minus one frame before a read. The number of lost frames is estimated as (wall time since the first data x rate) minus frames read, at that moment. The recorder counts these as suspected dropouts and does NOT insert silence for them. Reason: finding 7, `getLongFramePosition` stops when the buffer is full, so position minus read cannot see the loss.

- **Design D2'' (correction of D2' by the user after reviewing the findings):** the overflow test is as in D2' (`available()` at least the buffer size minus one frame before a read). The loss estimate is estimatedLost = max(0, wallFramesSinceFirstData - framesRead - availableFrames), with wallFramesSinceFirstData = round((now - tFirstData) x rate) and availableFrames = `available()` / frameBytes at that moment. D2' forgot to subtract the frames still waiting in the buffer, which overstates the loss by up to a whole buffer. One suspected dropout is counted per contiguous episode (an episode ends when `available()` falls below half the buffer); the recorder keeps the LARGEST estimate seen (cumulative, because frames read never include lost frames). No silence is inserted for lost frames.
- **User additions (flagged, may be vetoed):** a silence warning (peak below -90 dBFS for 3 s or more raises a "silent input" flag, shown by the UI in Phase B); a memory guard (an `OutOfMemoryError` while allocating the next chunk ends the recording with OUT_OF_MEMORY and keeps everything stored); single-use capture sources (after `stop()` or `close()` a source can never be started again; every recording uses a fresh source from a factory, following finding 8).

## A adaptations
Read first: `AudioSink`, `JavaSoundSink`, `SampleCodec`, `SampleSource`, `MemorySampleSource`, `ReadChecks`, `AddTrackCommand`, `Editor`, `Track`, `Project`, `MixPlan`, `StereoMixer`, the `PlaybackEngine` thread and listener conventions. No STOP-level question arose; nothing beyond small additions to existing classes.
1. **PCM16 decoding** reuses `SampleCodec.decode(bytes, frames, channels, WavEncoding.PCM_16, dest, 0)` unchanged (v / 32768f with the high byte sign-extended; it reads from byte 0, and the recorder decodes each block from its own buffer at 0). No new decoder.
2. **`CaptureSource`** follows `AudioSink`: it extends `AutoCloseable` with a `close()` that throws nothing; `read` returns whole frames. Single-use: `start()` after `stop()`/`close()`, and `open`/`start` after `close()`, throw `IllegalStateException`; `read`, `availableBytes`, `stop` and `close` stay safe on the real source (read 0, available 0 after close), so the safety net can never make the capture thread throw. The fake is stricter (read and available after close throw) so a D1' violation fails loudly.
3. **Listeners:** `Recorder.addListener`/`removeListener` (a `CopyOnWriteArrayList`, `RuntimeException`s from listeners ignored), as in `PlaybackEngine`; the settled constructor has no listener parameter. `stateChanged(RECORDING)` is delivered on the capture thread when it begins (the state is already RECORDING when `start()` returns).
4. **Constructor defaults:** `bufferFrames` 0 means `max(1, rate / 10)` and `maxFrames` 0 means `30 * 60 * rate`, both resolved in `start()` because the rate is known only then. Convenience constructor: `Recorder(CaptureSourceFactory)`.
5. **`stopAndWait`:** when idle it returns the most recent result (empty if there was none); on the capture thread it does not wait; a timeout of 0 means "do not wait". When the safety net (the source's `stop()`/`close()`) is used, the drain is skipped (the buffered bytes are unreadable after stop, finding 8) and the reason stays USER.
6. **Broken source:** a read that returns 0 without a stop request, a negative count, more than asked or a partial frame ends the recording with ERROR, like a read that throws. `errorMessage` is "The input device failed: <cause>".
7. **`RecordingResult.everClipped`** means the sustained-clipping warning (3') was raised at least once (`ClipWatch.everClipped` latches on the warning), not "one sample reached full scale". Flagged for the user: a single clipped sample is common and would make a post-recording message noisy.
8. **`ClipWatch` with less than one second of data:** the window is everything so far (so heavy clipping at the start warns at once).
9. **Order in a block:** the block is appended to the store before the counters change, so after an OUT_OF_MEMORY `framesRecorded()` equals the stored frames.
10. **Cap during the user drain:** the data is trimmed to the cap and the reason stays USER (the stop was requested first).
11. **D2'':** the estimate is recomputed every time the overflow condition holds (not only at the start of an episode) and the largest is kept; an overflow seen before any data counts as a dropout but estimates nothing (there is no tFirstData yet).
12. **`Editor`:** public constant `Editor.RECORD = "Record"`; refusals "the recording is empty" and "sample rate mismatch: the project is at X Hz, the recording at Y Hz"; `addRecording` clears `lastRefusal` like every edit.
13. **`ChunkedSampleSource`:** `DEFAULT_CHUNK_FRAMES`, `chunkFrames()`, a `Builder(sampleRate, channelCount)` convenience; `append` allocates all chunks it needs BEFORE copying and rolls them back on an error, so a failing block stores nothing; a factory result of the wrong shape is an `IllegalStateException`. Besides one chunk per 65536 frames, the internal chunk list grows occasionally (documented).
14. **`JavaSoundCaptureSource`:** `isLineSupported` first ("No usable input device for 16-bit stereo at 44100 Hz"), otherwise "Cannot open the default audio input for 16-bit stereo at 44100 Hz: <cause>".
15. **Fake read semantics:** the fake's `read` returns as soon as at least one frame is there (up to the length asked), where the real line waits for the whole length; this lets the tests fix the block boundaries. The gate holds a read AFTER it has taken its bytes, so the overflow check before the next read sees a burst fed during the hold.
16. **Test (b), "frames fed after stop()":** read as after the source's `stop()` in the end sequence (they are dropped, test asserted). Frames that arrive between `Recorder.stop()` and the thread noticing it (at most one block on a running device) are recorded, by design of an asynchronous stop.
17. **Test (c):** with no data a blocked read can only be woken by the safety net, so "returns within the timeout" is checked as "returns after one timeout plus the safety net" (150 ms timeout, 140-1500 ms asserted). "A fake that ignores the flag" is a fake whose read ignores `stop()` (only `close()` wakes it); a third case ignores both and shows `stopAndWait` returning empty instead of hanging.
18. **Extra tests beyond the list:** `FakeCaptureSourceTest` (5 tests that validate the fake against findings 7 and 8); in `RecorderTest`, the default buffer, the default cap, a fresh source for the second recording, and no-stall cases.
19. **`ArchitectureGuardTest`:** "model must not import audio" added to the existing rule table; "audio must not import edit or ui" and "edit must not import audio" were already enforced.
20. **Unchanged on purpose:** the Javadoc of `AudioDeviceException` still speaks of the "output device"; it is now thrown for the input too. Left as is ("No other class changes").
